01 / The workflow

Encryption without the ceremony.

No cloud account. No password form. Select, encrypt, and physically separate.

STEP 01

Choose your data.

Select one file or an entire folder, including nested folders.

STEP 02

Encrypt it locally.

The app generates fresh key material and encrypts the contents without uploading them.

STEP 03

Keep the key apart.

The encrypted file stays on the desktop. Its matching key goes to the USB.

02 / Designed to disappear

Complex inside.
Simple outside.

The interface handles key matching and file management, so you can focus on what you want to protect.

Automatic key discovery

Finds the matching key on USB, without relying on its filename.

Rename-friendly

Encrypted files and key files can be renamed independently.

Folder support

Preserves the regular file hierarchy and empty folders.

Local processing

No file content or key material is sent to a server.

Linux Mint desktop app

App menu shortcut, dedicated icon, optional system tray, and login autostart.

Streams large files

Chunked processing; performance depends on USB and disk speed.

03 / Get started

Desktop first.

The tested desktop workflow currently targets Linux Mint. Python launch scripts for Windows and macOS are included in the project, but have not been verified on those systems.

04 / Under the hood

Inspired by the
one-time pad.

Fresh OS-generated random key material, byte-wise XOR encryption, and HMAC-SHA256 authentication.

This is experimental cryptography, not an audited security product. A computer-generated keystream does not establish the mathematical perfect-secrecy guarantee of a strict one-time pad. The key occupies roughly as much space as the encrypted payload.

Keys must be backed up securely. If the USB is lost or fails and there is no backup, your encrypted files cannot be restored.

File names may be visible. Encrypted filenames normally retain the original name, though they can be changed. Symlinks and certain special entries are excluded from folder archives.
